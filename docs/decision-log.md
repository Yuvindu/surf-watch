# Decision Log — SurfWatch

| Date | Decision | Why | Alternatives considered | Impact | Owner |
|---|---|---|---|---|---|
| 2026-03-11 | Use Scrum with 1-week sprints | Iterative delivery + early validation | Waterfall, Spiral | Defines delivery cadence |  |
| 2026-03-11 | Project name: SurfWatch | Clear and relevant | RipWatch, WaveGuard | Repo/Jira naming |  |
| 2026-03-24 | Use the official RipVIS train/validation/test split at the video level | Prevents frame and temporal leakage and preserves the dataset's curated balance across viewpoints, durations, and rip-current types | Automatic random frame split, custom video split | Keeps entire source videos and derived frames/masks in one partition; test split remains untouched during training and tuning |  |
| 2026-04-08 | Convert RipVIS instance annotations into binary semantic segmentation masks for SurfWatch | The project treats rip-current detection as a binary semantic segmentation task rather than instance segmentation | Keep instance segmentation format throughout, switch model formulation to instance segmentation | Produces one rip/background ground-truth mask per frame for model training and validation |  |
| 2026-04-08 | Use the RipVIS validation split for quantitative evaluation and checkpoint selection | The public RipVIS test split is distributed as `test_without_annotations.json`, so local quantitative scoring on test is not available | Attempt custom relabeling of test, hold out a new internal test split from train | Makes validation the main local split for IoU, Dice, precision, and recall; test is reserved for qualitative inference on unseen videos |  |
| 2026-04-08 | Keep the raw RipVIS dataset outside the main SurfWatch Git repo and version only code/docs/manifests in SurfWatch | The full dataset and generated artifacts are too large for normal Git tracking and should remain separate from project code | Commit dataset files to the main repo, publish a derived dataset repo immediately, use Git LFS for everything | Preserves version history for scripts and documentation without bloating the main project repository |  |
| 2026-04-08 | Standardize dataloader preprocessing to fixed-size 512×512 inputs for the initial baseline pipeline | RipVIS frames have varying resolutions and orientations, which prevents default PyTorch batching without resizing | Custom collate with variable sizes, padding strategy, larger fixed resolution | Enables stable batching for baseline training and validation experiments |  |
