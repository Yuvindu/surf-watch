# Temporal Aggregation Strategy for SurfWatch

## Objective
Define the temporal aggregation strategy used in the SurfWatch MARSP pipeline for improving frame-to-frame segmentation stability.

## Motivation
Frame-level segmentation predictions are generated independently by the baseline SegFormer model. This can lead to flicker, unstable rip-current boundaries, and inconsistent region shape across adjacent frames.

A simple fixed temporal average can reduce this instability, but the literature context for RipVIS also highlights an important risk: applying temporal aggregation on moving-camera footage can reinforce misaligned predictions and increase false positives. For SurfWatch, this means temporal aggregation should not treat all neighboring frames as equally reliable.

## Selected method
The current MARSP implementation uses:

**Motion-adaptive sliding-window probability averaging**

This approach extends the earlier fixed sliding-window design by using motion metadata from the motion compensation stage to control how much neighboring frames influence the current prediction.

## Input format
The input to temporal aggregation is a time-ordered sequence of frame-level rip-current probability maps produced by the segmentation model before binary thresholding.

For the binary segmentation setting, each frame contributes:
- one rip-current probability map
- shape represented as `H x W`

In the current implementation, these probability maps are exported as grayscale probability videos for pipeline interoperability.

## Output format
For each frame, temporal aggregation produces:
- a temporally smoothed rip-current probability map
- a binary rip-current mask after thresholding

## Motion metadata input
Temporal aggregation also accepts motion metadata generated by the motion compensation stage.

This metadata includes per-frame information such as:
- transform success / fallback
- good match count
- inlier count
- translation in x and y
- translation magnitude
- estimated rotation

This information is converted into a per-frame motion score that is used to adapt the temporal aggregation behavior.

## Base window strategy
The base temporal window remains a centered **5-frame** window:

- `t-2`
- `t-1`
- `t`
- `t+1`
- `t+2`

However, this is now treated as the **maximum available local context**, not a fixed rule that is always applied equally.

## Motion-adaptive behavior
The current MARSP implementation adapts temporal aggregation in two ways.

### 1. Adaptive effective window size
The effective temporal radius is reduced when motion is stronger.

Conceptually:
- **low motion** → use the full local window
- **moderate motion** → reduce the window
- **high motion / failed alignment** → rely mainly or entirely on the current frame

This prevents unstable neighboring frames from influencing the target frame too strongly.

### 2. Motion-weighted neighbor influence
Neighboring frames are not averaged uniformly. Their contribution is weighted based on:
- temporal distance from the target frame
- motion score of the target frame
- motion score of the neighboring frame

Frames with stronger motion or unreliable alignment receive less influence during aggregation.

## Aggregation rule
For each target frame, the aggregated probability map is computed as a weighted average over the valid local temporal window.

The current frame always retains the strongest influence. Neighboring frames are downweighted when:
- they are farther away in time
- motion is stronger
- alignment is less reliable

If motion is too high or weighting becomes unreliable, the method falls back to the current frame probability map rather than forcing aggregation.

## Thresholding rule
The aggregated probability map is converted into a binary segmentation mask using a threshold of **0.5**:

- probability `>= 0.5` → rip current
- probability `< 0.5` → background

This threshold is sufficient for the current MARSP prototype and may be tuned later if needed.

## Edge handling
At the beginning and end of a video, a full centered window may not be available.

Current handling:
- use only the valid frames available within the sequence
- do not pad with synthetic or duplicated frames

Examples:
- frame `0` uses frames `[0, 1, 2]`
- frame `1` uses frames `[0, 1, 2, 3]`

## Edge cases
### Boundary frames
Use reduced valid windows when full temporal context is unavailable.

### Noisy isolated predictions
Short-window aggregation should suppress one-frame prediction spikes and drops, especially under low-motion conditions.

### Sudden scene changes
The current design assumes continuous footage. Scene-cut-aware handling remains future work.

### Motion compensation instability
If motion estimation fails or falls back for a frame pair, the corresponding motion score is increased so temporal aggregation becomes more conservative.

### Over-smoothing risk
The adaptive strategy is specifically designed to reduce the risk of over-smoothing during higher-motion segments by shrinking the effective temporal context and lowering neighbor weights.

### False-positive reinforcement in moving-camera footage
This is the main reason the strategy became motion-adaptive. Rather than averaging all neighboring predictions equally, the current approach reduces cross-frame influence when camera motion is stronger so that misaligned predictions are less likely to be reinforced.

## Rationale
Motion-adaptive sliding-window probability averaging is preferred for the current MARSP version because:
- it preserves confidence information better than majority voting
- it remains simpler and easier to reason about than more advanced fusion methods
- it reduces flicker and short-term instability in low-motion segments
- it responds more conservatively in moving-camera footage, where naive temporal averaging can increase false positives

## Future alternatives
The following methods may be evaluated later:
- exponential moving average with motion-aware decay
- confidence-weighted temporal fusion
- scene-cut-aware aggregation
- direct in-memory aggregation on raw model probabilities rather than video-encoded probability maps

## Current implementation note
The current MARSP pipeline applies temporal aggregation after frame-level SegFormer inference and uses motion metadata from the preprocessing stage to make aggregation adaptive rather than fixed.

Pipeline order:

`input video → motion compensation → SegFormer inference → motion-adaptive temporal aggregation`

## Conclusion
The current SurfWatch temporal aggregation strategy is no longer a simple fixed temporal average. It is a motion-adaptive probability fusion step designed to improve segmentation stability while reducing the risk of false-positive reinforcement in moving-camera footage. This makes it more appropriate for the MARSP pipeline and better aligned with both the project’s literature context and the current implementation.
